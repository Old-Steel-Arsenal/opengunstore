## `finalize`

`POST /api/method/ffl_core.api.inventory_count.finalize`

**Auth (derived from code):** Roles: Stock Manager / System Manager

Finalize a count: adjust the non-serialized differences and save the firearm report.

Posts one Stock Reconciliation for the non-serialized differences, dated the moment
the figures were worked out, so anything sold afterwards stacks on top of it.
Refused, with nothing posted, while a register sale (POS Invoice not yet closed) is
open on any row being adjusted: ERPNext takes that stock out only when the register
closes, so a quantity set now would be wrong by exactly that much.
Firearms are never adjusted here, no disposition is created and FastBound is not
called: a missing gun needs a person to look into it. A count with no quantity
entries at all (firearms only) finishes without a reconciliation.

| arg | type | required | default | description |
|---|---|---|---|---|
| `count` | string | yes | — | The Inventory Count name; must be open and have at least one scan. |
| `item_rows` | — | no | `None` | The rows to adjust, as [{item_code, warehouse}] (list or JSON), so staff can untick rows on the page. Left out = every row with a difference EXCEPT items nobody scanned: those are only adjusted (to 0) when listed here. Quantities are always worked out again here, never taken from the caller. |

**Returns:** {ok, stock_reconciliation, adjusted: [{item_code, warehouse, expected, adjust_to}], skipped: [{item_code, item_name, warehouse, counted, reason}], serial: {missing, unexpected, unknown}}.

## `scan`

`POST /api/method/ffl_core.api.inventory_count.scan`

**Auth (derived from code):** Roles: Stock User / Stock Manager / System Manager

Record one scan: a firearm's serial number or an item's barcode.

The code is tried as a serial number first (case and surrounding spaces ignored),
then as an item barcode (UPC). A serial adds the gun once; scanning it again changes nothing. A UPC adds 1 to
that item in ``warehouse``. A code that matches neither is saved as an unknown
barcode so it shows in the report.

| arg | type | required | default | description |
|---|---|---|---|---|
| `count` | string | yes | — | The Inventory Count name; must be open. |
| `code` | string | yes | — | What the scanner typed. |
| `warehouse` | string \| null | no | `None` | Where a UPC scan is being counted. Optional when the count covers one warehouse or the store's default warehouse is part of it. |

**Returns:** {result: serial|already|item|unknown|error, message, serial, item_code, item_name, warehouse, expected, counted, entry (the row to undo), warning}. ``result`` error means nothing was saved (the message says why).

## `create_item_with_options`

`POST /api/method/ffl_core.item_options.create_item_with_options`

**Auth (derived from code):** Requires create permission on Item (Frappe DocType permission check).

Create an item that comes in options: the template Item, any missing options (Item

Attributes) and values, and one variant Item per included combination — all or nothing.

Each variant copies the template's shared fields once (group, brand, description, photos,
tax and accounting defaults, flags) and has its own item code (its SKU), price (with the
register's Item Price), cost and pre-order slots. The template keeps no price, cost, UPC or
stock of its own.

| arg | type | required | default | description |
|---|---|---|---|---|
| `item` | — | yes | — | The Item form's document (dict or JSON), as the form would save it. ``item_code`` is required. |
| `options` | — | yes | — | ``[{name, values: [value, ...]}]`` in order (1–3 options); values in the order the storefront lists them. Names and values are matched to existing ones ignoring case. |
| `rows` | — | yes | — | ``[{values: {option: value}, include, sku, price, cost, preorder, eta}]`` — one per combination; unticked rows (``include`` 0) are skipped. An included row needs a SKU (letters, numbers and ``. _ / -``, not an existing item code) and a price above 0. |

**Returns:** {"template": the template's item code, "variants": [the variants' item codes]}.

**Raises:** ValidationError: Any row or option problem (all listed at once); nothing is written.

## `update_option_rows`

`POST /api/method/ffl_core.item_options.update_option_rows`

**Auth (derived from code):** Requires write permission on Item (Frappe DocType permission check).

Save the panel of an item that comes in options: edits to existing rows, and new rows for

values added to its options — one transaction.

An existing row is saved through an ordinary Item save (so the website and GunBroker pushes
run); a new price also becomes the register's price. Unticking a row disables that variant —
never deletes it — and ticking it again enables it.

| arg | type | required | default | description |
|---|---|---|---|---|
| `template` | string | yes | — | The Item that comes in options. |
| `rows` | — | yes | — | ``[{item_code, include?, price?, cost?, preorder?, eta?}]`` for existing rows (only the keys sent change), and ``[{values: {option: value}, include, sku, price, cost, preorder, eta}]`` for new combinations (created when included; same checks as :func:`create_item_with_options`). |
| `options` | — | no | `None` | ``[{name, values}]`` — the item's options in order with every value it shows, new ones included, in the order the storefront lists them (needed when new rows are sent; the option names can't change). Unused new values are kept on the option. |

**Returns:** :func:`item_options_state` after the save, plus ``"created"``: the new variants' item codes.

## `request_agreement`

`POST /api/method/ffl_core.agreements.request_agreement`

**Auth (derived from code):** Roles: Sales User / Sales Manager / Stock Manager / System Manager

Send a customer an agreement to sign.

Creates the customer's Pending copy of the template, or re-issues the one
already pending (its old link stops working and its text is rendered again).
While that copy still has a working link — the customer may be signing on the
tablet right now — nothing changes unless ``replace`` is 1: the answer is
``{"name", "link_open": True, "token_expires"}`` so the counter can ask first.

| arg | type | required | default | description |
|---|---|---|---|---|
| `customer` | string | yes | — | Customer name (document id). |
| `template` | string | yes | — | Agreement Template name; must be active. |
| `deliver` | string | no | `'qr'` | ``tablet`` — send the link to a paired signing tablet (``terminal``; ``ffl_core.signing_terminal``), which opens it by itself once the request commits (a caller that never commits sends nothing); ``qr`` — return the signing link and a QR code for the counter; ``email`` — email the link to the customer (refused when the customer has no email address); ``none`` — only create the Pending copy (a manager then records a paper copy on it). |
| `replace` | integer | no | `0` | 1 to re-issue even though the pending copy's link still works. |
| `terminal` | string \| null | no | `None` | Signing Terminal name, for ``tablet``; must be active and paired. |
| `serial_no` | string \| null | no | `None` | The gun, for an Each firearm sold template (required there). |

| `reference_doctype` | string \| null | no | `None` | For a Per document template (required there): the record's DocType. |
| `reference_name` | string \| null | no | `None` | That record's name; the caller must be able to read it, and the record's ``agreement_context()`` fills the text's placeholders. |

**Returns:** {"name": the Customer Agreement, "deliver", "token_expires"} plus, for ``qr``, "sign_url" and "qr_svg" (an SVG data URI); for ``email``, "email". The link itself is never stored.

## `submit_signature`

`POST /api/method/ffl_core.agreements.submit_signature`

**Auth (derived from code):** Guest — no session; the endpoint verifies the caller itself (HMAC signature, HTTP Basic credentials or a one-time token).

Sign an agreement through a one-time link (Guest).

Checked before anything is written: the "I agree" tick, the typed name, the
token (same error for every invalid one), the signature (a PNG of at most
500 KB and 2000 px with ink on it) and the age rule. A link opened as a QR
code at the counter, or on a paired signing tablet (its device key sent as
``terminal_secret``; the copy records which tablet), is recorded as signed on
a Tablet, an emailed one as Remote. The link is used up; the signed PDF is built and emailed afterwards.
When the template's text changed after the page was opened, nothing is signed
and the signer is asked to reload and read the new text. 10 calls an hour per
link and 300 per IP address.

| arg | type | required | default | description |
|---|---|---|---|---|
| `token` | string | yes | — | The token from the link's ``#t=`` fragment. |
| `signature` | string | yes | — | The drawn signature as a PNG data URL. |
| `agreed` | integer | yes | — | 1 — the signer ticked "I agree". |
| `signer_name` | string | yes | — | Name typed by the signer. |
| `participant_is_minor` | integer | no | `0` | 1 when the signer declares the participant is under 18 (ignored when the store keeps the customer's date of birth). |
| `signer_relationship` | string | no | `'Self'` | Self, or Parent / Guardian when signing for a minor. |
| `terminal_secret` | string \| null | no | `None` | The signing tablet's device key, when signed on one. |

**Returns:** {"signed": true, "store_name"}.

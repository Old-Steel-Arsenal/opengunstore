## `banned_order_rows`

`POST /api/method/ffl_core.customer_flags.banned_order_rows`

**Auth (derived from code):** Requires read permission on Customer (Frappe DocType permission check).

Which Pending Order rows belong to a Banned customer, for the page's red badge.

A web or GunBroker order is booked to a customer only once it has shipped, so
its buyer is looked up the way that booking will: a Woo order by its billing
email (customer email, then merged-email alias); a GunBroker order by its linked
customer, then the buyer's GunBroker id (field, then alias), then email.

| arg | type | required | default | description |
|---|---|---|---|---|
| `woo_orders` | list | str | no | `None` | Woo Online Order names on the page. |
| `gb_orders` | list | str | no | `None` | GunBroker Order names on the page. |
| `customers` | list | str | no | `None` | Customer names of the counter rows. |

**Returns:** {"woo": [names], "gb": [names], "customers": [names]} — only the Banned ones.

## `override_customer_ban`

`POST /api/method/ffl_core.customer_flags.override_customer_ban`

**Auth (derived from code):** Roles: Sales Manager / System Manager

Manager lets a Banned customer be served for the next 30 minutes.

Opens the window every counter screen and the server-side sale gate read
(``ban_override_until`` / ``ban_override_by``) and records who and why on the
customer's timeline. The customer stays Banned.

| arg | type | required | default | description |
|---|---|---|---|---|
| `customer` | string | yes | — | Customer name (document id); must be Banned. |
| `reason` | string | yes | — | Why the sale is allowed (required, kept on the timeline). |

**Returns:** {"customer": name, "override_until": the window's end, "by": the manager}.

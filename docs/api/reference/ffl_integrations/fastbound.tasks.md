## `push_serial_to_fastbound`

`POST /api/method/ffl_integrations.fastbound.tasks.push_serial_to_fastbound`

**Auth (derived from code):** Requires write permission on Serial No (Frappe DocType permission check).

Push a post-acquisition manufacturer / importer correction for ONE

firearm to FastBound, editing the bound-book item in place (PUT /Items/{id})
— no delete/recreate, FastBound audit-logs the edit.

Called synchronously from the Serial No form's "sync to FastBound?" confirm
after an operator edits a per-unit manufacturer / importer.

| arg | type | required | default | description |
|---|---|---|---|---|
| `serial` | string | yes | — | Serial No name (must carry a fastbound_item_id). |

**Returns:** {"ok": True, "item_id": ...} on success; {"ok": False, "reason": "not_in_fastbound" | "not_configured"} for the expected not-pushed cases (rather than raising) so the form can show a tidy message. A store running with FastBound switched off reports "not_configured" too — from the operator's side it is the same fact, and the edit they just made is saved locally either way.

**Raises:** FastBoundError: Genuine API failures.
